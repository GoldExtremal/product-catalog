# Мок-сервер · Задание 1. Product Catalog

## Запуск

```bash
docker build -t mock-api .
docker run --rm -p 4000:4000 mock-api
# или без Docker: node server.js   (Node.js 20+, зависимостей нет)
```

В своём `docker-compose.yml` подключите мок как сервис:

```yaml
services:
  mock-api:
    build: ./mock-api
    ports: ["4000:4000"]
```

Проверка: `curl localhost:4000/health`.

## Служебные эндпоинты

- `GET /__chaos` — текущие настройки сбоев, `POST /__chaos` — изменить (передаются только нужные поля).
- `POST /__reset` — сбросить данные, счётчики и настройки сбоев к исходным.
- `latency_ms` — задержка ответа: число или диапазон `[мин, макс]`; `error_rate` — доля ответов `500` (от 0 до 1).
- Служебные эндпоинты (`/__*`, `/api/__stats/*`) не подвержены задержкам и ошибкам.
- CORS разрешён для любого origin, но удобнее проксировать `/api` через dev-сервер или nginx.

## Особенности

- 500 товаров, данные одинаковые при каждом запуске.
- `limit` — до 100, по умолчанию 24. Некорректный параметр — `400 { "error": "invalid_param", "param": "..." }`.
- `q` ищет подстроку в названии без учёта регистра.
- Картинки `/img/<id>.jpg` отдаются как SVG-заглушки 600×600, задержкам не подвержены.
- По умолчанию `latency_ms: [50, 300]`. Для проверки гонок: `{ "latency_ms": [50, 2000] }`.
